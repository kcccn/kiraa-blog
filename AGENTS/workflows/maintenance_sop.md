# 标准化作业流程：样式修改与功能添加

## 流程 A：修改样式

### A-1 需求分析与规格定义

**输入**：用户描述的样式需求或问题报告

**操作**：

1. 确认需求涉及的页面类型：
   - 全局（所有页面）→ 修改 `:root` 块中的 CSS 变量
   - 文章页 → 修改 `.single .content` 选择器内的规则
   - 特定组件 → 定位对应的 CSS 类名
2. 确认需求涉及的渲染模式：亮色 / 暗色 / 双端
3. 将需求转化为可量化的 CSS 属性规格（颜色值、尺寸、间距等）

**输出**：样式规格文档，包含目标选择器、属性名、目标值、适用模式

**判断标准**：规格文档必须包含具体的 CSS 属性和值，不接受模糊描述（如"好看一点"、"更醒目"）

**异常处理**：

| 异常 | 处理方式 |
|------|----------|
| 需求涉及 `themes/FixIt/` 内文件 | 拒绝执行，说明必须通过覆盖方式实现 |
| 需求无法通过 CSS 变量覆盖实现 | 降级为 SCSS 选择器覆盖，记录降级原因 |
| 需求与现有 Vue 风格配色冲突 | 标注冲突点，要求用户确认优先级 |

---

### A-2 相关变量/配置项定位

**输入**：A-1 输出的样式规格文档

**操作**：

1. 在 `assets/css/_custom.scss` 中搜索是否已有相关覆盖规则
2. 在 `themes/FixIt/assets/css/_variables.scss` 中查找对应的 SCSS 变量默认值
3. 在 `themes/FixIt/assets/css/_core/_root.scss` 中查找对应的 CSS 变量输出（`--fi-*` 命名空间）
4. 在 `themes/FixIt/assets/css/_maps/_colors.scss` 中查找主题色映射
5. 记录当前值和目标值的差异

**输出**：变量定位表

| 字段 | 内容 |
|------|------|
| 目标属性 | CSS 属性名 |
| 当前值 | 现有覆盖值或主题默认值 |
| 目标值 | 需要修改为的值 |
| 定位文件 | 变量定义所在文件及行号 |
| 覆盖方式 | CSS 变量覆盖 / SCSS 选择器覆盖 |

**判断标准**：定位结果必须精确到文件路径和行号

**异常处理**：

| 异常 | 处理方式 |
|------|----------|
| 目标属性无对应 CSS 变量 | 使用 SCSS 选择器直接覆盖，记录原因 |
| 目标属性被 `!important` 覆盖 | 新规则同样使用 `!important`，标注优先级链 |
| 暗色模式无独立变量 | 使用 `[data-theme='dark']` 选择器单独覆写 |

---

### A-3 覆盖代码编写

**输入**：A-2 输出的变量定位表

**操作**：

1. **CSS 变量覆盖**（优先方案）：
   - 在 `assets/css/_custom.scss` 的 `:root` 块中添加或修改变量
   - 暗色模式变量在 `[data-theme='dark']` 上下文中覆盖
2. **SCSS 选择器覆盖**（降级方案）：
   - 在 `assets/css/_custom.scss` 中添加选择器规则
   - 文章页样式限定在 `.single .content {}` 内
   - 行内代码样式必须使用 `!important`
3. 编写代码，遵循项目现有格式：
   - 使用 4 空格缩进
   - 注释使用 `/* */` 格式
   - 属性声明每行一个

**输出**：代码变更内容（diff 格式）

**判断标准**：

- 代码不包含对 `themes/FixIt/` 的任何引用或修改
- 选择器特异性足以覆盖主题默认值
- 暗色模式适配完整

**异常处理**：

| 异常 | 处理方式 |
|------|----------|
| 覆盖规则不生效 | 检查选择器特异性，必要时提升至 `!important` |
| 影响非目标页面 | 收窄选择器范围，添加页面类型限定 |

---

### A-4 暗色/亮色模式兼容性验证

**输入**：A-3 输出的代码变更

**操作**：

1. 启动本地 Hugo 服务器：
   ```bash
   hugo server --disableFastRender --ignoreCache
   ```
2. 在浏览器中打开 `http://localhost:1313/`
3. 逐项验证以下检查清单：

| 检查项 | 亮色模式 | 暗色模式 |
|--------|----------|----------|
| 目标属性视觉效果 | □ 符合预期 | □ 符合预期 |
| 文字与背景对比度 | □ 可读 | □ 可读 |
| 行内代码颜色与背景 | □ 可读 | □ 可读 |
| 链接颜色与悬停效果 | □ 可区分 | □ 可区分 |
| 数学公式渲染 | □ 正常 | □ 正常 |
| 代码块语法高亮 | □ 正常 | □ 正常 |
| 引用块样式 | □ 正常 | □ 正常 |
| 非目标页面未受影响 | □ 正常 | □ 正常 |

4. 切换暗色模式：点击页面右下角主题切换按钮，或使用浏览器 DevTools 修改 `<html>` 的 `data-theme` 属性

**输出**：验证结果表（通过/未通过 + 截图路径）

**判断标准**：所有检查项必须为"通过"状态

**异常处理**：

| 异常 | 处理方式 |
|------|----------|
| 暗色模式下对比度不足 | 调整暗色模式对应变量值，确保 WCAG AA 标准（对比度 ≥ 4.5:1） |
| 数学公式颜色异常 | 检查 `.katex { color: inherit !important; }` 是否被覆盖 |
| 切换模式后样式未更新 | 清理浏览器缓存，确认 Hugo 资源缓存已清理 |

---

### A-5 文档更新与版本控制

**输入**：A-4 通过的验证结果

**操作**：

1. 更新 `AGENTS/knowledge/blog_specs.md` 中受影响的规范条目
2. 使用 `AGENTS/templates/patch_format.md` 格式输出完整补丁
3. Git 提交信息格式：
   ```
   style: <简要描述修改内容>
   
   - 修改的 CSS 变量/选择器
   - 影响的页面类型
   - 亮色/暗色模式验证状态
   ```

**输出**：Git commit

**判断标准**：提交信息包含修改内容、影响范围、验证状态

---

## 流程 B：添加新功能

### B-1 需求分析与功能规格

**输入**：用户描述的功能需求

**操作**：

1. 确认功能类型：
   - Hugo 配置项调整 → 修改 `hugo.toml`
   - 新增短代码支持 → 确认 FixIt 主题是否已内置
   - 新增前端库 → 评估引入方式
   - 新增页面模板 → 评估模板覆盖方案
2. 查阅 FixIt 主题文档（`themes/FixIt/README.md`）确认是否已有内置支持
3. 评估实现路径：
   - **路径 A**：`hugo.toml` 配置启用（优先）
   - **路径 B**：项目 `layouts/` 模板覆盖
   - **路径 C**：`assets/` 资源扩展
   - **路径 D**：`content/` 内容结构调整

**输出**：功能规格文档，包含实现路径、涉及文件、配置参数

**判断标准**：必须优先选择路径 A（配置启用），仅在配置无法满足时降级

**异常处理**：

| 异常 | 处理方式 |
|------|----------|
| 功能需要修改主题源码 | 拒绝执行，说明需等待主题更新或通过模板覆盖实现 |
| 功能与现有配置冲突 | 列出冲突项，要求用户确认优先级 |
| 功能需要新增前端依赖 | 评估对构建体积和加载性能的影响 |

---

### B-2 配置项/模板定位

**输入**：B-1 输出的功能规格文档

**操作**：

1. 在 `hugo.toml` 中查找相关配置项
2. 在 `themes/FixIt/layouts/` 中查找相关模板文件
3. 在 FixIt 主题文档中查找参数说明
4. 确认配置合并策略（`_merge = "shallow"` 的行为）

**输出**：配置/模板定位表

| 字段 | 内容 |
|------|------|
| 功能名称 | 需求描述 |
| 实现路径 | A/B/C/D |
| 涉及文件 | 需要创建或修改的文件路径列表 |
| 配置参数 | 需要添加或修改的 hugo.toml 参数 |
| 依赖项 | 前端库、Hugo 版本要求等 |

**判断标准**：定位结果必须包含完整的参数名和可选值范围

---

### B-3 代码编写与集成

**输入**：B-2 输出的配置/模板定位表

**操作**：

1. **路径 A（配置启用）**：
   - 在 `hugo.toml` 中添加或修改配置项
   - 遵循现有配置格式和注释风格
   - 使用 `_merge = "shallow"` 保持与主题默认值的兼容
2. **路径 B（模板覆盖）**：
   - 在项目根目录 `layouts/` 下创建与主题相同路径的模板文件
   - 以主题模板为基础进行修改，不得直接复制主题模板全文
   - 使用 Hugo 模板继承（`{{ define }}` / `{{ block }}`）减少重复
3. **路径 C（资源扩展）**：
   - 在 `assets/` 目录下添加资源文件
   - 利用 Hugo 管道处理（SCSS 编译、JS 压缩）
4. **路径 D（内容调整）**：
   - 修改 `archetypes/` 模板
   - 更新 Front Matter 规范

**输出**：代码变更内容（diff 格式）

**判断标准**：

- 未修改 `themes/FixIt/` 下的任何文件
- 配置项使用正确的合并策略
- 新增模板文件路径与主题模板路径一致

---

### B-4 功能验证

**输入**：B-3 输出的代码变更

**操作**：

1. 清理 Hugo 缓存并启动服务器：
   ```bash
   rm -rf resources/ public/
   hugo server --disableFastRender --ignoreCache
   ```
2. 验证功能检查清单：

| 检查项 | 验证方式 |
|--------|----------|
| 功能正常工作 | 手动操作验证 |
| 亮色模式兼容 | 切换主题验证 |
| 暗色模式兼容 | 切换主题验证 |
| 移动端响应式 | 浏览器窗口缩放验证 |
| 现有功能未受影响 | 回归测试首页、文章页、归档页 |
| 构建无报错 | 检查终端输出和浏览器控制台 |

3. 执行生产构建验证：
   ```bash
   hugo --minify
   ```
   确认 `public/` 目录生成完整，无构建错误

**输出**：验证结果表（通过/未通过 + 问题描述）

**判断标准**：所有检查项必须为"通过"状态

**异常处理**：

| 异常 | 处理方式 |
|------|----------|
| 构建报错 | 根据错误信息定位问题，检查模板语法和配置格式 |
| 功能部分生效 | 检查 Hugo 配置合并行为，确认主题默认值未被意外覆盖 |
| 移动端布局异常 | 添加响应式媒体查询或检查 Flex/Grid 布局 |

---

### B-5 文档更新与版本控制

**输入**：B-4 通过的验证结果

**操作**：

1. 更新 `AGENTS/knowledge/blog_specs.md` 中受影响的规范条目
2. 更新 `AGENTS/doc.md` 中受影响的架构描述（如目录结构、配置项等）
3. 使用 `AGENTS/templates/patch_format.md` 格式输出完整补丁
4. Git 提交信息格式：
   ```
   feat: <简要描述新增功能>
   
   - 实现路径（配置/模板/资源/内容）
   - 涉及文件列表
   - 亮色/暗色模式验证状态
   - 生产构建验证状态
   ```

**输出**：Git commit

**判断标准**：提交信息包含功能描述、实现路径、验证状态
